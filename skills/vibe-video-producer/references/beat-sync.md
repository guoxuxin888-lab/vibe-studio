# 音乐拍格、动作和音效共同调度

适用：有配音、现成音乐、角色表演或外部动作音效的片子。选曲和混音读 sound.md；本页解决时间怎么对齐、动作怎么成立、最终导出怎么验证。纯字幕片不因此加音效，长片不因此每拍切镜。

## 1. 建立同一份时间表

先锁已确认的配音、字幕及原音轨SHA。台词与语义边界不为卡拍移动；落地、停步、书名显现等视觉重点再选择附近合适拍点。图文阅读时允许停住，不用持续摇晃制造“有动作”。

现成曲记录BPM、拍号、源相位phase、源偏移offset、可用时长、进鼓/稀疏段/高潮/收束及测拍可信度。B=60/BPM；源拍点phase+k×B，影片拍点T=phase+k×B-offset。自动估计要排除半速/倍速歧义，在曲首/中/尾和转段复查相位；母带或剪接变化后重测。当前useMusic的beat/pulse从影片0起算；选曲起点若不是源拍点，须按上述相位公式生成cue或明确适配hook，不能仍把t/B当实际拍格。

沿用当前工程认可的score与timeline构建接口：语义cue保留原声秒数，音乐动作cue用拍数计算。现成曲使用单独映射时，确认构建器真能生成这些cue，不盲跑原创合成器覆盖原曲或已有混音。字幕只读已锁定真源，画面和声音读取相同命名事件。

### 动作对到字上

有配音时，先用配音的 RMS 包络（10 毫秒一格）找出每句里音节的起点，和 SRT 的句子对起来，得到关键字（名字、数字、“死”“当兵”这类重音字）的实际秒数。然后每个动作取离那个字最近的拍：拍点 = T0 + k × 一拍，k 取整。动作可以比字早一点完成（约 0.2 秒内），不要晚太多。这样画面同时跟着字和鼓点走。

每个强落点记：语义任务、目标音乐时间、动作准备/完成/恢复、FX资产与标记点、实际可见帧、导出后音频延迟。动作的“完成或接触”对拍，不能只让开始时间对拍。

## 2. 从目标拍换算实际画面帧

规划帧号frame=round(T×fps)，实际时间frame/fps。对于约定要强同步的落点，使用最近帧；本地强落点以半帧误差作为技术检查起点，仍需看听，不声称通用感知阈值。

插值动作以这个量化后的完成时间收束，准备动作提前若干拍、恢复随后若干拍。不仅检查t>=目标小数：30fps下8.502347秒的首个“之后”帧是256，而最近帧是255（8.5秒），两种写法可能差一帧。长片的普通出字、停顿和阅读由原声与语义决定。

角色需要配合重心、手脚、视线和道具：

- 走动有起步、交替支撑、重心转移、停步；有意跳跃可以离地，非跳跃的支撑脚按旋转/缩放后的世界坐标回贴地面，不能只查父组y。
- 抬手要有可见的手端轨迹。关节转了角度但圆手几乎没挪动，不算清楚的指引。需要伸臂时保持角色形态，手端锚点函数与画面使用同一变换，别凭角度猜接触位置。
- 看向目标再指引；入场、停住、读字、退场错开主焦点。需要托、拿、碰时查实际手/道具接点；只是指引则给手和物边留净空。
- 看动态包围轮廓：手、头巾尾带、鞋底、操纵杆都算。整条路线避开人脸与文字；避不开就改站位/路线/遮挡层级。品牌角色先读原组件与动作/音效映射，私有适配不覆盖原素材。

## 3. 音效对齐标记主峰

优先用真实资产池和映射。落地/接触/重点状态变化才触发，先判断原曲的鼓点是否已足够；不要每个小动作都叠一声。

先解码到项目采样率，记录源文件SHA与目标标记偏移p。短促单峰可用独立FX的最大绝对PCM值作可复现候选；慢起音、多峰等须看听后选可感知冲击点，机器最大值不等于已听准。

目标音峰为T，理想起点onset=T-p；贴入样本n=round(onset×sampleRate)。实际峰时间=(n+sourcePeakSample)/sampleRate。若含滤镜延迟，测处理后偏移；若起点会为负，调整选段/准备期或换音色，不硬裁前导。

分别保留VO/BGM/FX与float总线。检查独立FX的实际PCM标记峰，再检查与实际动作帧的差；不能拿含配音和音乐的总混音最大值冒充单独音效峰。外部品牌音效单独登记来源与授权/私有范围，不伪装成通用合成音效目录。

## 4. 定长混音与资源约束

短音效布置可用明确N=round(duration×sampleRate)的PCM数组：有界解码源音、按样本贴入，输出前检查有限值、声道和样本数。浮点总线相加后限峰，最后转整数PCM；整数中间文件若已削平，后级limiter无法恢复。

所有解码、滤镜、编码子进程同时限定运行时间、输出时长和输出字节数/pipe maxBuffer。时限与字节预算随本片规模计算；atrim不是唯一资源保护，不使用无限apad或未定长延迟图。保护上限触发即停止依赖，不能把被截断的文件继续混音。核退出码、文件封口、样本数、大小及完整解码，保留原音源和旧版本。

## 5. 对最终MP4验内容同步

WAV正确不保证导出音轨正确。分别记录视频帧数/时长、PCM样本数、编码音轨/容器时长和start_time；编码尾填充预算与正文内容延迟分开检查，start_time=0不证明同步。

有界解码最终音轨，与最终mix WAV比较前/中/后三个有明显内容的窗口，约定正lag=导出音晚；记录每窗范围、相关峰、lagSamples/lagMs、置信度。固定同量lag指向整轨新增延迟，lag随位置变化再查采样率/变速或漂移。低能量、低相关、重复内容或搜索边缘峰视为证据不足，改选窗口，不报告通过。

工程工具在vibe-studio/tools维护单一实现；以下命令从工程根运行，工具参数以--help为准，audit可用--ffmpeg/--ffprobe显式指定，mux用FFMPEG_PATH/FFPROBE_PATH；也可加入当前进程PATH，不写死某个用户的安装路径：

~~~bash
node tools/audit-audio-sync.mjs mix.wav final.mp4 --fps 30 --tolerance-ms 1 --report qc-new.json
~~~

需要修复导出音轨时保留失败版，从原最终PCM WAV单次AAC编码，与已定画面stream-copy封装新文件，然后重测同样窗口。不要盲裁掉开头或按猜测前移语音：

~~~bash
node tools/mux-pcm-audio.mjs picture.mp4 mix.wav final-new.mp4 films/my-film/timeline.json
~~~

mux只封装，不代替同步检查。示例中的my-film换成本片真实slug；第四参数直接读取该timeline的duration/frames/fps，也可传已核的本片秒数。输入画面帧数/时长必须与计划一致，否则工具在生成前拒绝，不能照抄案例16.6秒截短全片。输出已存在时拒绝覆盖；48kHz PCM需先覆盖计划时长。重测后再核声音I/TP/LRA、完整解码、浏览器播放/跳转及强落点附近的内容延迟。无法单独分离编码后的FX时，写明音峰是“独立FX PCM标记＋导出附近混合窗延迟”的推定，别声称直接量到了独立AAC FX峰。

## 6. 一个可回查的例子

一条 16.6 秒配音样片：BPM 112.91，源曲相位 0.082 秒，取曲偏移 = 相位 + 12 拍。三个独立音效的主峰落在第 2/16/23 拍，对应 30fps 第 32/255/367 帧，画面落点减音峰分别是 +3.9/−2.4/+11.2 毫秒。

旧导出 v2 虽然 start_time=0，三个语音窗都多了 2048 样本（42.7 毫秒）延迟；从原 WAV 单次 AAC 编码、画面直接拷贝的 v3 三窗都是 0 样本。这个例子的 BPM、拍数、坐标、增益都不通用，也不证明传播效果，只说明“WAV 对了，MP4 不一定对”，一定要对最终文件做三窗检查。
