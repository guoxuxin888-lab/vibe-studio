# 项目设计

## 一个原则

短片里，观众的身体先于大脑做出反应。音乐决定他们什么时候紧张、什么时候放松，所以音乐不是最后铺上去的东西，是全片的总谱。

```
内容包（讲什么）
   ↓
导演方案（世界观、贯穿物、画风、情绪弧）
   ↓
总谱 score.mjs ──→ 音频 + MIDI
   ↓
时间线 timeline.json（小节、拍、和弦、段落张力、动机、提示点、真实响度）
   ↓
画面 Film.tsx · 动效 · 字幕 · 音效全部读它
```

改一个速度，所有事件一起移动。不会出现音乐改了、动作全错位的情况。

## 两种创作方式

| | 原创 | 参考 |
|---|---|---|
| 起点 | 这个概念的质地是什么，世界如何运转 | 一部成立的案例，为什么成立 |
| 第一步 | 写一句世界观 | `npm run reference`，逐段填参考卡 |
| 学什么 | 从画风库和音乐库选起点，再改 | 结构、节奏、动效的使用场合 |
| 不做什么 | 不默认黑底金字 | 不用原文、原画面、原音乐 |
| 产物 | `treatment.md` | `treatment.md`，写明学了什么、换了什么 |

两条路收束到同一份导演方案，后面的流程完全一样。如果说不出参考片“为什么成立”，就只是在抄表面。

## 一部片的文件

```
films/<slug>/
  content-package.md  内容包。字幕和事实只有这一个来源
  treatment.md        导演方案。逐小节写音乐、画面、字
  score.mjs           总谱。段落、和声、动机、提示点、音效
  score.mid           导出的 MIDI
  timeline.json       生成的时间线，画面只读它
  Film.tsx            画面
public/films/<slug>/  音频和素材（不进仓库，可重新生成）
out/                  成片（不进仓库）
```

## 四个库

- **画风库** `libraries/styles/*.json`：配色、质感、人物、光、运动语言、推荐音乐、生图提示词，以及不该做什么。`previews/` 只展示配色和字体，不是成品画面。
- **音乐库** `libraries/music/moods.json`：情绪预设，含速度、调式、和声进行、动机和配器。`auditions/` 是可试听的版本，都是引擎生成的。
- **音效库** `libraries/sfx/catalog.json`：每种音效的用途和该怎么定音。音效是配方，不是录音。
- **动效库** `src/motion` 和 `libraries/motion/README.md`：组件都按拍计时，颜色从画风来，不写死品牌。

加一种东西只要加一个文件，`npm run doctor` 会检查它完整不完整。

## 质量关口

1. **内容包**：状态、选题卡、事实来源不齐，`npm run new` 不开工。
2. **导演方案**：世界观和逐小节表写完再写画面。
3. **15 秒样片**：只做开头到点题，配真实音乐。风格不对在这里停。
4. **`npm run doctor`**：提示点越界、时间线过期、字幕不在内容包里、私有文件被跟踪，都会报错。
5. **人看人听**：机器查不出好不好听、好不好看。

## 明确不做的

- 不预测爆款，也不打分。
- 不在字幕里改字。要改回到内容包。
- 不收录别人的作品。参考拆解只留在本地 `references/private/`。

## 下一步

引擎的合成音色偏简单，真正要发布的片子，可以用导出的 MIDI 换真人或高质量音源。音乐生成服务可以作为另一种来源接入，但时间线还得从谱面来，否则画面就读不到和弦和动机。
