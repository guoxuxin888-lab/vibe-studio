# Vibe 视频制作

这个 Skill 决定**观众看到和听到什么**，交付项目文件和成片。讲什么由 `vibe-content-planner` 的内容包决定。

所有命令都在 vibe-studio 工程根目录运行。音乐提供动作拍格；有配音时以已确认音轨的台词和语义边界为准，再安排重音动作。先定音乐与 cue，再做画面，不为卡拍拉伸配音或改字幕时码。

结论分三档：**数据**、**拉片**（样本的共同做法）、**假设**。贴拍、响度、硬切和点赞几乎没有相关（**数据**），所以制作的目标是过线并把比喻讲清楚，不要为贴合某个数字去改片。音乐先行是创作方法，不是涨数据的依据（**假设**）。工程实测只说明当前素材与版本的技术检查结果，不升格为听感或传播数据。

## 开工前

1. 工程根目录有 `profile.local.md` 就先读它。那是使用者自己的账号规则：署名角色、品牌色和字体、敏感词替换、封面要求、内容包放在哪。它和本 Skill 冲突时以它为准。没有就按本 Skill 的默认做。
2. 跑 `npm run doctor`。缺 Node、ffmpeg、中文字体或浏览器时，按它的提示补齐再开工。

## 先判断入口

| 用户手上有什么 | 从哪开始 |
|---|---|
| 内容包，状态是 `待制作` | 第 1 步 |
| 没有内容包，只有题或稿 | 先转 `vibe-content-planner`。用户坚持直接做时，说明缺什么，补一份最小内容包再开始 |
| 已有片子 | 读 `films/<slug>/treatment.md`，从记录的进度继续 |
| 有成片或对标片 | 跑 `node tools/measure.mjs <视频>`，给修改意见 |

默认规则：
- 参考片只学动效、音效和场合，颜色字体用自己的，除非用户点名照参考片。
- **不改字。** 字幕和内容包逐字一致。字放不下、事实有疑问时，提回策划，不在工程里改。
- 默认不做封面，用户点名要时再做。

## 第 1 步：定创作方式，建片

用户给了案例就走**参考**，没给就走**原创**。不确定时问一句，方法读 `references/visual.md`。

建片前区分视觉方式与音频来源。原创合成音乐用 `npm run new`；有固定配音或现成曲时走 `references/production.md` 的“已有音轨建片”。

```bash
npm run reference -- <案例.mp4> --id <id>     # 只有参考方式需要
npm run new -- <slug> --package <内容包.md> --mode original|reference [--reference <id>] --style <画风> --mood <情绪>
```

两条建片分支都先校验内容包，不过就把缺什么告诉用户；创建后把内容包状态改成 `制作中`。

## 第 2 步：导演方案

读 `references/visual.md`，填 `treatment.md`：世界观，贯穿物怎么变形，主角，画风，两个角色色，亮度曲线，首尾画面。

画风先问“这个概念的质地是什么”，不要默认黑底金字。给 2 个方向让用户选时，用静帧或概念图说话。AI 图逐张查“现实里是这样吗”，图中文字逐字核对。

## 第 3 步：选曲或写谱，建立拍格

读 `references/sound.md`。原创时把张力、动机、休止和 cue 写进 `score.mjs`，再 `npm run music -- <slug>`；使用现成曲时先比选情绪弧、时长和人声让位，实测 BPM、相位与段落，记录源偏移，不调用合成音乐覆盖它。现成曲先查清授权，未查清的不能进公开仓库。

配音、现成音乐、角色表演或外部音效参与时，继续读 `references/beat-sync.md`：先测出配音里关键字的起点，每个动作取离那个字最近的拍；视觉按动作完成帧，音效按可听主峰对齐，不能只对齐文件起点。

## 第 4 步：约 15 秒样片

读 `references/production.md`。以约 15 秒为起点（配音片可到 30 秒）覆盖完整开场语义、贯穿物、点题大字及最容易失败的动作链，配上选定或写好的音乐；不截断句尾或动作。

**闸门：用户看过也听过样片才做全片。** 这是最省返工的一步。

## 第 5 步：全片和交片

按 `references/production.md` 分层制作、分章审看。可复用且无私有品牌依赖的动效按拍写进 `src/motion/` 入库；品牌角色和私有素材留在本片目录，不进公共库。用 AI 生成图片或视频前，先告诉用户要花多少钱、生成几条，等用户同意。

交片前：

```bash
npm run doctor
node tools/measure.mjs <成片.mp4>
node tools/audit-audio-sync.mjs <mix.wav> <成片.mp4> --fps 30 --tolerance-ms 1 --report <qc.json>
```

偏离范围时判断是否有意为之。过一遍 `references/production.md` 的交片自检。

把成片路径、最终时长写回内容包的“制作记录”，状态改成 `待发布`，告诉用户下一步回 `vibe-content-planner` 写发布文案和复盘。

## 汇报方式

每个闸门只给决定所需的信息：看什么、依据（标明档次）、风险、要用户选什么。样片和成片给路径，并说清哪些地方没看过或没听过。
