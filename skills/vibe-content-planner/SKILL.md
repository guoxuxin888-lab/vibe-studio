# Vibe 内容策划

这个 Skill 决定**这条片讲什么、观众读到什么**，交付一份内容包。画面、音乐和工程归 `vibe-video-producer`。

目标是提高命中率，不是保证爆。样本全是爆款，没有播放量，自家片还需要各自验证。结论分三档：**数据**（有互动数据）、**拉片**（样本的共同做法）、**假设**（判断，待验证）。不要预测“这条能爆”，也不要打爆款分。

同一账号的片子能差 4–9 倍，而贴拍、响度、硬切在爆款内部拉不开差距（**数据**）。所以这里是最值得花时间的环节：**题目 > 第一屏 > 贯穿物**。

## 开工前

工程根目录有 `profile.local.md` 就先读它。那是使用者自己的账号规则：账号定位、写作习惯和禁用说法、敏感词替换、内容包放在哪、交稿前要跑的检查命令。它和本 Skill 冲突时以它为准；它里面写的检查命令，交稿前照跑。

缺事实或意图不明时，先查用户给的资料，查不到再一次问完，不补造。

## 先判断入口

| 用户手上有什么 | 从哪开始 |
|---|---|
| 只有方向或想要题 | 第 1 步 |
| 有题，没稿 | 先过四关，再第 2 步 |
| 有稿或只改开头 | 按指定范围修改、核对来源；完整交付时再补事实表和内容包，定点改稿保留其余正文 |
| 成片交回，要发布 | 第 4 步 |
| 发布后有数据 | 第 5 步 |

## 故事类入口

历史、讲书、人物故事，先读 `references/story-hooks.md`；需要对照示例再读 `references/story-examples.md`。区分主事件、对外话题与开头入口：主事件限定本集因果主线，对外话题表达观众为什么在意，开头决定怎样引入。成片可以按“话题 → 事件 → 转折与结果 → 回答话题”展开；核对事件是否足以回答话题。

故事稿用自然口语：白话写人物与场面，难懂处用现代类比并标明是比方，用户确认过的句子原样保留。已有连载排期时，用它约束本集事件范围与前后衔接。

## 第 1 步：定目标和选题

读 `references/topic.md`。

1. 判断这条主要要什么：收藏、转发、评论，还是快速起量。
2. 新方向按需要出候选，用四关筛；故事类按故事参考中的人物处境、知识疑问、具体事件与来源筛。已有选题或连载排期时直接在其范围内推进。
3. 推荐 2–3 个，每个写明目标、片型、时长、第一句、贯穿物、依据来源、最像的样本类型、风险。

**闸门 1：用户选定题目才往下做。**

## 第 2 步：写稿和事实表

读 `references/script.md`。声音形式按用户要求；未明确时默认纯字幕，并说明默认。故事口播按自然段写完整意思，字幕分屏在录音后从 SRT 派生。

事实表逐条列年份、人名、数字、研究、引言和来源。查不到的不写，示意的标明。

```bash
node <skill目录>/scripts/check_script.mjs <内容包或稿子> --seconds <目标秒数>
```

口播或配音稿在命令末尾加 `--voiceover`，只估时与查正文，不套字幕的首句和拆屏字数提示；实际时长以试读或录音为准。

工具只查格式与估时，不证明事实、吸引力或风格通过。故事稿还要检查：是否给陌生观众清楚的观看理由，主事件能否回答对外话题，开头的疑问是否被正文回答，人物动作与对白是否有来源，用户确认句是否原样保留。

## 第 3 步：内容包

按 `references/content-package.md` 的格式保存，用户确认稿子后把状态改成 `待制作`。

**闸门 2：用户确认稿子才交制作。** 这时贯穿物、第一句、时长、声音形式已定；画风、配色、音乐留给制作。

交付时告诉用户：下一步用 `vibe-video-producer`，内容包路径是什么。

## 第 4 步：发布文案

成片交回后写标题、正文和话题。概念字幕片可参考 `Vibe知识大赏｜概念：一句话`；故事片优先表达已确定的对外话题，不直接拿内部事件名替代，也不固定为问句。正文按片子顺序把事情讲一遍，事实都要在事实表里。话题可用 #vibe知识大赏 加 1–2 个题材标签（样本多数带这个话题，对你账号的作用未验证）。是否标注用了哪个 AI 工具由用户定。只填写，不替用户点发布。

## 第 5 步：复盘

读 `references/review.md`。第 3、7 天抓数据写入台账，每条只改一处。第一批 5 条风格不变、只换题，先测出题目标准。用自家数据更新 `references/topic.md` 的假设。

## 证据

`references/evidence.md` 是 81 条样本的统计结论（片型、开头、时长、互动比例）。样本是别人的作品，只学结构和手法，不照搬原句和画面。

## 汇报方式

每个闸门只给决定所需的信息：推荐、依据（标明档次）、风险、要用户选什么。
